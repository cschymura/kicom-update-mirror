## New development-only implementation
- KiComMembraneEventReceipt.php: standalone isolated staging SQLite reservation ledger at a bounded disposable /tmp/kicom-membrane-receipts-*/receipts.sqlite path, not the KiCom live DB. Uses SQLite BEGIN IMMEDIATE and full synchronous WAL with a UNIQUE event-hash primary key; stores only event-hash, raw-message-hash, UTC insertion time, and NEEDS_RECONCILIATION state, no raw message text, credentials or destination.
- reserve() atomically distinguishes NEW_DURABLE_RECEIPT, EXISTING_RECEIPT_REQUIRES_RECONCILIATION, EVENT_ID_HASH_COLLISION, and RECEIPT_DATABASE_UNAVAILABLE. A provider retry or restart never creates a second reservation for the same event identity. Every returned state has action_authorized=false, delivery_authorized=false, automatic_replay_allowed=false, runtime_ack_verified=false. The module has no Slack send, dispatch, ACK publish, delete or replay interface.
- Critically, a local SQLite receipt is NOT an atomic commit of remote Slack delivery or an independent anti-rollback trust root; even NEW_DURABLE_RECEIPT never authorizes external action. An uncertain prior external effect requires separately verified reconciliation and a protected action boundary. Durability under abrupt machine power loss, backup rollback and real host filesystem conditions is NOT proven by these process/restart tests.
- test-event-receipt.php plus test-receipt-worker.php: 17 isolated regressions for invalid paths/hashes, unique insertion, retry, different bytes for reused ID, reopen, a separate worker exiting immediately after reservation, uncertain-post-crash no-replay, competing SQLite writer lock and failed transaction without partial insertion, and no public dispatch method. No real messages were sent.
- The existing .github/workflows/test-0927-membrane.yml now lints and runs these tests without changing the native R3 HTTP/DEV/Slack/Mail/update routes or the Membrane passive shadow. The prior 189 isolated tests remain included.
