Instead, DEV-93 now binds EVERY private consent to exactly ONE independently issued access-token hash, committed atomically with original PKCE code redemption; DEV-89 independent SQLite consent reader and DEV-91 native MCP gate both require this exact token-hash join. Multiple authorized chats therefore cannot collide by accumulating valid consent rows. Pending consent rows have NULL token_hash and do NOT approve any bearer.
